## 우선순위 높음

### 1. 방 안 대화 듣다가 "자비스, 어때?"에 답하기 (isair)
- 말소리가 들리면 받아 적어 **메모리에만 120초** 쌓는다. 디스크에 저장하지 않고, 멈추면 지운다.
- 문장 **어디에든** 이름이 들어 있으면 후보가 된다. 이름을 잘못 받아 적은 말(예: "자비쓰")도 별명으로 등록하고, 비슷한 글자 비율 0.78 이상이면 같은 이름으로 본다.
- 이름이 들렸다고 바로 답하지 않는다. 작은 모델에게 "이게 나한테 한 말이야?"를 JSON(`directed`, `stop`, `confidence`)으로 묻는다. "친구한테 자비스 얘기를 했어" 같은 말은 아니라고 판단한다.
- 이름도 없고 답한 직후도 아닌 그냥 수다는 **AI에 보내지 않는다**. 받아 적기 비용만 든다.
- 답할 때는 쌓인 대화를 "참고 자료(지시 아님)"로 넣어 "그거 어때?"의 "그거"를 알아듣게 한다.
- 답을 마친 뒤 3초 동안은 이름 없이 이어 말해도 받는다("핫 윈도").
- 우리에게: 회의 녹음·듣기 모드와 잘 맞는다. 단, 방 안 말을 계속 받아 적는 것이라 **본인 동의와 켜고 끄기 단추**가 꼭 필요하다.

### 2. 스피커 소리(에코)와 "멈춰" 처리 강화 (isair)
- 지금 우리는 "방금 읽은 답과 같으면 무시"만 한다.
- isair는 **언제 무슨 단어를 읽고 있었는지 시간을 맞춰** 비교한다(비슷한 정도 85 이상). 에코 뒤에 사람 말이 붙어 있으면 앞부분만 잘라 내고 사람 말은 살린다.
- "멈춰/그만/조용" 같은 말은 AI 없이 글자로 바로 알아듣는다. 말하는 중에는 녹음 길이를 3초로 줄여 "멈춰"가 빨리 처리되게 한다.
- 일시 정지·재시작 때마다 번호(세대)를 올려, 예전 번호의 받아 적기·답은 버린다.

### 3. 받아 적기 헛소리 거르기 (isair)
- Whisper가 조용할 때 지어내는 글을 막는다: `no_speech_prob` 0.5 이상이면 버림, 확신도가 낮으면 버림, 소리 세기가 너무 작으면 버림, 앞 문장에 이어 쓰기 끄기.
- 토스 기기처럼 멀리서 듣는 마이크에서 잘못 깨어나는 것을 줄인다. 우리 whisper.cpp 설정에서 같은 값을 쓸 수 있는지 확인이 필요하다.

### 4. 아침 브리핑을 미리 만들어 두기 (OpenJarvis)
- 정해진 시각(기본 오전 6시)에 PC가 일정·날씨 등을 모은다 → AI가 **한 번만** 200단어 이내로 쓴다 → 소리 파일로 저장한다.
- 토스 기기는 그 파일만 틀면 된다. 기기 부담이 거의 없다.
- 규칙: 받은 자료에 있는 사실만 말하기, 실패한 자료는 말하지 않기, 표·이모지 없이.
- 알아 둘 점: OpenJarvis의 Kokoro 음성은 **한국어가 없다**. 우리는 지금처럼 OS·안드로이드 음성을 쓴다.
- OpenJarvis의 "브리핑 점수 매겨 다시 쓰기"는 코드가 빠져 있어 실제로 동작하지 않는다.

### 5. 승인 단계 나누기와 기억하기 (OpenJarvis)
- 작업마다 단계를 둔다: 사소함(바로 실행) / 낮음(한 번 묻고 기억) / 보통(기억이 없으면 묻기) / 높음(항상 묻기).
- "항상 허락/항상 거절"은 낮음·보통에만 허용한다. 대기 중인 승인은 24시간 뒤 사라진다.
- 확인해 줄 사람이 없으면 실행하지 않는다.
- 약점: OpenJarvis는 AI가 단계를 스스로 정한다. 우리는 **PC 규칙으로 단계를 정해야** 한다(AI가 "사소함"이라고 우겨도 무시).
- 우리 승인 대기 작업(Mission Control)에 바로 붙일 수 있다.

## 우선순위 보통

### 6. 기억 자동 제안 (두 저장소)
- 대화가 5분 멈추면 그날 대화를 200단어로 요약(일기)한다(isair).
- 요약에서 "오래 갈 사실"만 뽑는다. 한 번 더 검사해 날씨·인사·AI 자신의 추천 같은 것은 버린다(isair).
- 뽑은 사실은 중복을 지우고 최대 1000개만 둔다. 믿을 수 없는 사실은 따로 두고 사람이 확인해야 쓴다(OpenJarvis).
- 우리에게: 바로 저장하지 말고 **"기억할까요?" 제안 목록**으로 보여 주고 승인한 것만 넣는다(지금의 승인 원칙 유지).
- 매번 넣는 짧은 "내 정보 요약"은 USER 1200자, 지시 600자로 제한한다(isair).

### 7. 비밀 값 가리기 (isair)
- 이메일, 카드 번호, API 키, 토큰, 비밀번호, 인증 번호를 정규식으로 `[가림]` 처리한다. AI에 보내기 전과 기록에 남기기 전에 한다.
- 지금 우리는 기억에 저장할 때 비밀처럼 보이면 거절만 한다. 대화와 로그에도 가리기를 더하면 좋다.

### 8. 켜짐 점검과 "닥터" (OpenJarvis)
- `/health`가 Ollama까지 확인한다(`/api/tags`, 2초 안에 답 없으면 503).
- 점검 명령이 항목마다 정상/주의/실패와 고치는 방법을 알려 준다. 예: "모델 없음 → ollama pull gemma4:12b".
- 우리 화면의 "장치 점검"과 짝으로, PC 쪽 점검(서버·Ollama·모델·whisper·인증서)을 만들 수 있다.

### 9. 모델 받기를 튼튼하게 (isair)
- 별도 프로세스에서 받고 5분이 넘으면 끊는다. 너무 많은 요청(429) 오류는 2, 4, 8, 16초 뒤 다시 받는다. 디스크 부족·인증서 문제는 다시 받지 않고 원인을 알려 준다. 받다 만 파일은 남겨서 이어 받는다.
- 리뷰에서 본 가장 흔한 불만이 "처음 켤 때 모델 받다 멈춤"이었다.

### 10. 빠른 모델과 큰 모델 나누기 (isair)
- 작은 모델: "나한테 한 말인지" 판단, 도구 고르기, 기억 위치 찾기.
- 큰 모델: 답, 요약.
- 저전력 모드에서는 Ollama `keep_alive`를 1분으로 줄여 메모리를 비운다(보통 30분).
- 우리는 이미 질문 종류에 따라 생각하기(think)를 켜고 끈다(`src/conversation/reasoning.js`). 여기에 작은 모델 단계를 더하는 식이다.
