# JARVIS Hybrid 2.0 Constitution

## Core Principles

### I. 사용자 통제
인증은 사용자가 한다. 위험 변경·외부 전송은 대상·내용·영향을 보여 주고 승인을 받아야 한다(MUST).
승인은 정확한 내용 버전(해시)에 연결한다. 내용이 바뀌면 이전 승인은 무효다.
거절·취소된 작업은 실행하지 않으며, 같은 작업은 한 번만 실행한다(MUST).
Quick Actions도 같은 승인 경로를 쓴다. 승인 우회 경로를 만들지 않는다.

### II. 자연스러운 한국어 대화
듣기·생성·재생 상태를 구분한다. 끼어들기는 생성과 재생을 함께 중단하고 오래된 응답을 폐기한다.
자연스러움은 한국어 실제 청취로 평가하고 지연은 실제로 쓰는 기기(Mac·Windows 각각)에서 측정한다.

### III. 개인 자료 보호
기억·회의·음성의 저장과 삭제를 사용자가 제어한다. 삭제는 실제 저장소에서 지운다.
비밀 키는 코드·로그·기억에 넣지 않는다(MUST). 비밀처럼 보이는 값은 저장을 거부한다.
공급자 오류를 이유로 다른 외부 서비스로 자동 전송하지 않는다.

### IV. 증거가 있는 완료
요구·작업·동작 검사 결과를 연결한다. 모의 응답·Windows 실기·Mac 실기를 구분해 기록한다. 한 기기 결과로 다른 기기를 검증했다고 쓰지 않는다.
미검증을 성공으로 쓰지 않는다. 작은 기능 단위로 구현·검사·수정·재검사한다.

### V. 범위와 원본 보존
원본 명세 확보 후 대조한다. 현재 초안을 원본으로 부르지 않는다.
프로젝트 밖 파일과 전역 설정을 바꾸지 않는다. 커밋·푸시·PR은 명시 요청 때만 한다.
기기와 오픈소스는 공식 자료·이용 조건·실기 증거를 확인한다.

## 잠정 개발 범위와 제약

- 원본 확보 전에는 이 기기 안에서 검사할 수 있는 기능만 구현한다: Mission Control 승인, 기억 CRUD,
  Quick Actions, 공급자 계약, 그리고 사용자가 승인한 범위(로컬 음성 입출력·받아쓰기·회의 녹음, 캐릭터 설정, 로컬 화면).
  원본과 다를 수 있으므로 모두 잠정으로 두고 원본 확보 후 대조한다.
- 실제 유료 API 호출, 개인 자료 외부 전송, 녹음, 다운로드, Mac·기기 검증은 사용자 승인과 환경이 준비된 뒤에만 한다.
  승인은 그 범위에만 쓰고, 받은 승인은 tasks.md 또는 BLOCKERS.md에 날짜와 함께 남긴다.
- 잠정 기술 선택은 의존성이 적고 Windows·macOS 둘 다에서 돌아가야 하며, 선택 근거를 plan.md에 남긴다.
  원본 스택과 충돌하면 원본 확인 후 다시 정한다.

## 개발 흐름과 품질 관문

- 각 기능은 자동 검사(단위·재시작 복원 포함)를 통과해야 완료다.
- 실제 실행한 명령과 결과를 tasks.md에, 막힘·미검증·재개 방법을 BLOCKERS.md에 남긴다.
- 실제 완료한 작업만 tasks.md에 체크한다.

## Governance

이 문서는 이번 요청을 기준으로 작성한 잠정 원칙이다. 현재 사용자 요청이 이전 문서와 충돌하면 현재 요청을 우선한다.
개정 시 Sync Impact Report에 변경 이유를 남기고 버전을 올린다(원칙 삭제·재정의 MAJOR, 절 추가 MINOR,
문구 수정 PATCH). 원본 확보 후 충돌과 변경 이유를 기록한다. 계획·작업은 Constitution Check로 준수를 확인한다.
