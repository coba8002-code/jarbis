## 단계 구분

- **구현·검사함(Windows)**: US2 전체, US3(기억·공급자 어댑터·전송 승인·로컬 Ollama 실제 검사),
  US1 중 끼어들기 로직·음성 출력·마이크 입력·로컬 받아쓰기(whisper.cpp)·에코 대책·빠른 답/자동 생각,
  US4 중 캐릭터 설정(잠정), US5 중 녹취 시간·삭제 규칙·회의 파일 가져오기·회의 마이크 녹음, 두 OS 공통 로컬 화면(FR-013).
  마이크가 들어가는 기능은 이 PC에 마이크가 없어 합성 음성을 넣은 가짜 마이크로만 확인했다(2026-11-14).
- **남음**: 원본 대조, 실제 마이크·스피커 확인, 클라우드 API 실제 검사(키), macOS 실행(Mac),
  실제 청취(사용자), 캐릭터 시각 요소·US6 토스 프론트(원본·기기).

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 한국어 음성 대화와 끼어들기 (Priority: P1, 일부 구현: 끼어들기 로직·음성 출력·마이크 입력·받아쓰기)

한국어 질문에 음성으로 답한다. 답변 도중 새 발화가 오면 생성과 재생을 취소하며 이전 답변이 다시 나오지 않는다.
Mac과 Windows PC 각각의 실제 마이크·스피커로 검사한다. 권한 거부, 장치 해제, 연결 단절을 안내하고 재시도할 수 있어야 한다.

**Why this priority**: 제품의 핵심 경험이다. Windows에서 기기 없이 검사할 수 있는 부분은 구현했고, 실제 마이크·청취·Mac 확인은 남았다.

**Independent Test**: Mac과 Windows PC 각각의 실기에서 질문→응답→끼어들기→새 응답 흐름을 녹화·청취한다.

### User Story 2 - Mission Control과 Quick Actions (Priority: P1, 1단계)

사용자가 위험 작업이나 외부 전송을 요청하면 대상·내용·영향이 보이는 미션이 승인 대기에 들어간다.
사용자는 승인 또는 거절한다. Quick Action도 같은 승인 경로를 쓴다.

**Why this priority**: 모든 위험 작업의 안전장치다. 기기 없이 검사할 수 있다.

**Independent Test**: 로컬 명령으로 미션을 만들고 승인·거절·수정·재시작을 수행해 실행 기록을 확인한다.

**Acceptance Scenarios**:

1. **Given** 새 미션, **When** 승인 전 실행을 시도하면, **Then** 실행되지 않고 "승인 필요"를 알린다.
2. **Given** 대기 미션, **When** 거절하면, **Then** 이후 어떤 실행 요청도 실행되지 않는다.
3. **Given** 승인된 미션, **When** 내용을 바꾸면, **Then** 다시 승인 대기가 되고 이전 승인으로는 실행할 수 없다.
4. **Given** 승인된 미션, **When** 실행을 두 번 이상(동시 포함) 요청하면, **Then** 정확히 한 번만 실행된다.
5. **Given** 대기·승인 미션이 있는 상태, **When** 앱을 다시 시작하면, **Then** 상태와 내용이 그대로 복원되고 실행된 미션은 다시 실행되지 않는다.
6. **Given** Quick Action, **When** 실행을 요청하면, **Then** 미션이 만들어져 1~5와 같은 규칙을 따른다.
7. **Given** 실행 중 실패, **When** 결과를 보면, **Then** 실패와 이유가 기록되고 자동 재실행되지 않는다.

### User Story 3 - 기억과 네 AI 공급자 (Priority: P2, 1단계는 기억 CRUD·모의 계약만)

사용자는 기억을 저장·조회·수정·삭제한다. 재시작 후에도 남고, 삭제한 기억은 다시 나오지 않는다.
ChatGPT/OpenAI, Claude, Grok, Ollama는 공통 대화·스트리밍·오류·취소 계약을 쓴다.
ChatGPT 웹 로그인과 API 접근을 구분한다. 실패 시 다른 공급자로 무단 전송하지 않는다.
Ollama 서버·모델이 없으면 이를 알린다. 모의 검사와 실제 API 검사를 구분한다.

**Why this priority**: 개인화와 대화 품질의 기반이다. 실제 API는 비용·전송 승인이 필요해 모의 계약까지만 한다.

**Independent Test**: 로컬 명령으로 기억 CRUD·재시작·검색을 확인하고, 모의 공급자로 스트리밍·취소·오류를 확인한다.

**Acceptance Scenarios**:

1. **Given** 빈 저장소, **When** 기억을 저장하고 조회하면, **Then** 같은 내용이 나온다.
2. **Given** 저장된 기억, **When** 수정하면, **Then** 조회 결과가 바뀌고 수정 시각이 갱신된다.
3. **Given** 저장된 기억, **When** 삭제하면, **Then** 조회·검색·재시작 후에도 나오지 않는다.
4. **Given** API 키처럼 보이는 문자열, **When** 기억으로 저장하면, **Then** 저장이 거부된다.
5. **Given** 모의 공급자, **When** 대화를 요청하면, **Then** 조각 단위 응답이 순서대로 오고 끝 신호가 온다.
6. **Given** 진행 중 응답, **When** 취소하면, **Then** 이후 조각이 더 오지 않는다.
7. **Given** 공급자 오류, **When** 오류가 나면, **Then** 분류된 오류를 받고 다른 공급자로 자동 전송되지 않는다.

### User Story 4 - 캐릭터 스튜디오 (Priority: P2, 일부 잠정 구현: 설정·적용·목소리)

오리지널 캐릭터·목소리 미리 보기, 적용, 저장, 재시작 후 복원을 검사한다.
듣기·생각·말하기 상태를 대화와 연결하며 취소 시 복구한다. 자산 출처·이용 조건을 기록한다.

### User Story 5 - 회의 녹음과 타임스탬프 (Priority: P2, 일부 구현: 시간·삭제 규칙)

사용자가 녹음을 시작·중지하며 녹음 중 표시가 보인다. 녹취 시간은 녹음 시작 기준이며 순서가 뒤집히거나 음성 길이를 넘지 않는다.
시간을 눌러 해당 음성을 재생한다. 원음·녹취 삭제, 저장 실패, 앱 종료를 검사한다. 외부 전사는 승인을 거친다.

### User Story 6 - 토스 프론트 호환성 (Priority: P3, 보류)

정확한 제품·버전·공식 문서·연결 방식을 확인한 후 실제 장치로 입력·출력·재연결을 검사한다.
현재는 특정 기기나 UI 라이브러리라고 가정하지 않는다. 지원·부분 지원·지원 안 됨·미검증을 근거와 함께 보고한다.

### Edge Cases

- 같은 미션에 승인 요청이 동시에 두 번 오는 경우 → 실행은 한 번.
- 실행 도중 앱이 꺼진 경우 → 재시작 후 "실행 중"을 자동 재실행하지 않고 "중단됨"으로 표시해 사용자 판단을 받는다.
- 이미 실행·거절된 미션의 내용 변경 → 거부.
- 없는 기억 ID의 수정·삭제 → "없음" 오류.
- 저장 파일이 손상·잠김 → 오류를 알리고 자료를 덮어쓰지 않는다.
- 기억을 담은 외부 전송 미션이 승인된 뒤 그 기억을 고치거나 지움 → 실행 시 보내지 않고 실패로 기록, 새 요청 필요.
- 주소가 루프백이 아닌 Ollama → 외부 공급자로 본다.

## Requirements *(mandatory)*

### Functional Requirements

- FR-001: 한국어 음성 대화 — M1 Max와 Windows PC 각각. (출력: OS 내장 음성 합성 계층 구현, Windows 한국어 음성으로 WAV 합성 확인. 입력: 브라우저 마이크 녹음 → 이 기기 안 whisper.cpp 받아쓰기, 말하기 버튼·듣기 모드·에코 대책 구현(2026-11-14 녹음 승인 후). Windows에서 가짜 마이크로만 확인, 실제 마이크·Mac은 미검증)
- FR-001a: 대화는 기본으로 "빠른 답"(모델의 생각 단계 생략, 지원 공급자만)을 쓰고 사용자가 끌 수 있다. (2026-11-14 사용자 결정, 원본 확인 후 재검토)
  - 계산·추론으로 보이는 질문은 빠른 답이어도 생각해서 답한다("자동 생각", 기본 켬, 끌 수 있음). (2026-11-14 사용자 결정)
- FR-002: 끼어들기 시 생성·재생 취소 및 오래된 응답 폐기. (기기 없는 차례 관리 로직만 1단계에서 구현·검사. 발화 감지·실제 재생·지연은 Mac 실기 필요)
- FR-003: 캐릭터 설정과 이용 가능한 자산 관리. (잠정 구현: 이름·성격·말투·목소리·자산(출처·이용 조건 필수) 저장, 적용·재시작 후 유지, 말투를 대화에, 목소리를 음성 출력에 반영, 목소리 미리 듣기, 상태 표시. 그림·입 모양 등 시각 요소는 원본 확인 후)
  - FR-003a (잠정, 원본 없음, 2026-11-14): 캐릭터마다 단순한 오리지널 도형 얼굴(모양·색·눈)을 코드로 그린다. 외부 그림 자산·기존 캐릭터 모사는 쓰지 않는다. 상태(대기·듣기·생각·말하기)를 얼굴로 보이고, 말하는 동안 입이 일정한 박자로 열리고 닫힌다(소리에 맞춘 음소 립싱크가 아님). 캐릭터 탭에서 저장 전 미리 보기·취소, 적용 뒤 대화 탭 표시, 재시작 후 복원, 멈추기·재생 끝나면 대기로 돌아간다. 움직임 줄이기 설정이면 입 움직임을 멈춘다.
- FR-004: 사용자 제어가 가능한 지속 기억 — 저장·조회·검색·수정·삭제, 재시작 후 유지. (1단계)
- FR-005: 네 공급자 공통 계약과 선택 — 1단계는 모의 공급자로 계약 검사만. (1단계 일부)
- FR-006: 승인 대기·승인·거절·취소, 내용 버전 연결, 내용 변경 시 재승인, 중복 실행 방지, 재시작 복원. (1단계)
- FR-007: 같은 승인 정책을 쓰는 Quick Actions. (1단계)
  - FR-007a (2026-11-14): 실제 로컬 Quick Action "기억 검색"·"회의록 검색". 승인 화면에 검색어·대상(이 기기 기억/회의)·영향을 보인다. 승인 전에는 결과가 없고, 거절·취소·중복 실행 규칙은 다른 미션과 같다. 미션 결과에는 찾은 항목의 번호(회의는 구간 번호·시간)만 저장하고 원문은 저장하지 않는다. 화면은 결과를 볼 때 현재 자료를 다시 읽으므로 지운 기억·녹취는 다시 보이지 않는다. 검색어는 승인한 미션 내용으로 남는다(비밀처럼 보이는 검색어는 거부). 외부 전송·파일 삭제·명령 실행은 하지 않는다.
- FR-008: 회의 원음·녹취·시간 탐색·삭제. (녹취 시간 규칙·위치 찾기·삭제·재시작 복원, 회의 음성 파일 가져오기, 회의 마이크 녹음(원음 바로 저장·녹음 중 회의록)·시간 눌러 재생을 Windows에서 구현. 받아쓰기는 이 기기 안에서만. 실제 마이크·Mac은 미검증, 외부 전사는 없음)
  - 잠정 규칙: 멈출 때 정해진 음성 길이를 넘는 구간은 길이로 자르고, 길이 이상에서 시작한 구간은 지운다. 녹음 중 꺼진 회의는 중단으로 두고 녹취는 남긴다.
  - FR-008a (2026-11-14): 회의 제목·녹취 글을 검색하고, 결과는 회의별로 시간 구간(시작·끝)을 보인다. 결과의 시간을 누르면 그 위치부터 원음을 재생한다. 검색어의 `%`·`_`·`\`·따옴표 같은 글자는 글자 그대로 찾는다. 지운 회의·녹취는 검색되지 않는다.
  - FR-008b (2026-11-14): 회의 마이크 녹음 조각은 순서 번호(`seq`)를 붙여 보낸다. 같은 번호·같은 내용이 다시 오면(응답 유실 뒤 재전송) 원음에 다시 붙이지 않고 받아쓰기도 다시 하지 않으며 처음 결과를 돌려준다. 같은 번호에 다른 내용, 건너뛴 번호는 거부한다. 번호 없는 옛 호출은 예전처럼 붙인다(중복 방지 없음).
  - FR-008c (2026-11-14): 화면에서 회의를 지우면 재생 중인 원음을 멈추고, 화면이 들고 있던 원음 사본(blob URL)을 지운다.
- FR-009: 대상 확인 후 토스 프론트 실기 검증. (보류)
- FR-010: 비밀 키 보호 — 기억·기록에 비밀처럼 보이는 값 저장 거부. 개인 자료 전송 승인. (1단계 일부)
  - FR-010a (잠정, 원본 확인 전): 개인 자료(1단계는 기억)를 외부 공급자로 보내는 대화는 Mission 승인 뒤에만 보낸다.
    승인 화면에 공급자·주소·모델·질문·기억 원문·영향을 보인다. 승인 뒤 기억이 바뀌거나 지워지면 보내지 않는다.
    미션에는 기억 원문 대신 기억 번호와 해시만 저장해 삭제한 기억이 미션 기록에 남지 않게 한다.
    로컬 공급자(루프백 주소)로 보내거나, 개인 자료 없이 사용자가 고른 공급자로 질문만 보내는 경우는 승인 없이 보낸다.
- FR-010b: 지우거나 고친 개인 자료(기억·캐릭터·녹취)의 원문은 DB 파일과 WAL 파일에도 남기지 않는다(헌법 III, 2026-11-13 분석 C1).
- FR-011: 모든 미션 상태 변화를 기록(감사 기록)으로 남긴다. (1단계)
- FR-012: 로컬에서 한 번의 명령으로 실행·검사할 수 있는 최소 구조. (1단계)
- FR-013: macOS와 Windows PC 각각에서 단독 실행한다. 같은 화면(브라우저로 여는 로컬 화면)과 같은 명령을 쓴다. 기기 간 연결·동기화는 하지 않는다. 화면 서버는 그 기기 안(127.0.0.1)에서만 열린다. 실행마다 새 토큰과 Host 검사로 다른 사이트·다른 기기의 접근을 막는다. 같은 기기 안 다른 프로그램이 화면 주소를 열어 토큰을 얻는 것은 막지 않는다(수용한 위험, 원본 확인 후 재검토).
- FR-014 (2026-11-15 사용자 요청): 단축키 판 — 메인 화면(/jarvis)에 스트림덱 같은 큰 버튼(최대 24개). 버튼은 자비스 기능(물어보기·화면 열기·소리 켬·끔·멈추기·브리핑 듣기)과 PC 조작(프로그램 열기·단축키 보내기·웹 주소 열기)을 한다.
  - PC 조작은 쉘을 거치지 않고 정해 둔 프로그램(.exe·.lnk·.url / Mac .app)·키 이름·http(s) 주소만 쓴다. PC 조작 버튼은 이 PC 화면(127.0.0.1·localhost, USB로 묶인 기기 포함)에서만 만들고 고칠 수 있다. 다른 기기는 누르기만 한다.
- FR-015 (2026-11-15 사용자 요청·결정: 보기 + 추가·완료, 브리핑에 넣기): 구글 캘린더(기본 캘린더)·구글 Tasks(기본 목록) 연동.
  - 사용자가 만든 OAuth 클라이언트(데스크톱 앱)로 사용자가 직접 로그인한다(PKCE·state, 이 PC 127.0.0.1로 돌아옴, 연결은 이 PC 화면에서만). 열쇠는 데이터 폴더 google-token.json에만 두고 화면·기록에 내보내지 않는다.
  - 메인 화면 타일(오늘 일정·남은 할 일)에서 "일정·할 일" 화면으로 바로 간다. 일정 추가·할 일 추가·완료는 확인 창을 거친 뒤에만 구글에 쓴다(서버도 confirm: true 필요). 지우기는 하지 않는다.
  - 아침 브리핑에 오늘 일정·할 일을 넣는다(이 기기 안 모델만). 일정·할 일 글은 클라우드 AI로 보내지 않는다.
- FR-016 (2026-11-15 사용자 요청): 캐릭터 모션 — 한 번 하는 동작 16가지, 상태별 반복, 대기 잔동작, 머리 위 감정 표시, 답 내용 반응, 얼굴 누르기, 친구별 성격(기획: docs/CHARACTER_MOTION.md). 움직임 줄이기·쉬는 화면에서는 멈춘다.
- FR-017 (2026-11-15 사용자 결정: "토론 기능" = 회의 의견·결론 정리): 회의 녹취를 이 기기 안 모델(Ollama)에만 보내 요약·나온 의견(시간)·정한 것·할 일·남은 질문으로 정리한다. 클라우드 공급자로는 보내지 않고, 이 기기 안 모델이 없으면 하지 않는다.
  - 받아쓰기는 말한 사람을 구분하지 못하므로 녹취에 이름이 나올 때만 맡은 사람을 적는다. 녹취에 없는 내용을 지어내지 않게 요청하고, 의견 시간은 실제 녹취 시간 범위 안인 것만 남긴다. 긴 녹취는 약 8000자씩(최대 8조각) 나눠 정리한 뒤 합친다.
  - 정리는 회의마다 하나 저장하고, 회의나 녹취를 지우면 함께 지운다(FR-010b). 녹음 중인 회의는 정리하지 않는다.
  - 설정 → 회의에서 회의마다 정리하고 보며, 의견 시간을 누르면 그 위치부터 원음을 듣는다. 메인 화면에서 회의 녹음을 끝내면 받아 적은 말이 있을 때 이어서 정리하고 짧게 알린다.

### Key Entities

- **Mission**: 종류, 대상, 내용, 영향, 내용 버전(해시), 상태(대기·승인·거절·취소·실행 중·완료·실패·중단), 승인한 버전, 결과.
- **MissionEvent**: 미션 상태 변화 기록(시각, 이전·이후 상태).
- **QuickAction**: 이름, 미션 종류, 기본 내용. 실행 시 미션을 만든다.
- **MemoryEntry**: 내용, 태그, 생성·수정 시각.
- **ProviderConfig**: 공급자 이름, 비밀 키 참조만(값 없음).
- **Turn**: 대화 차례(상태 대기·듣기·생각·말하기, 끊김 여부). 메모리에만 둔다.
- **CharacterProfile**: 이름, 성격·말투, 목소리, 자산(출처·이용 조건). 적용 캐릭터는 Settings에 저장.
- **Meeting / TranscriptSegment**: 회의(상태·길이·원음 파일), 녹취 구간(시작·끝 ms, 글).
- **Settings**: 적용 캐릭터, 소리 읽기 켜짐, 빠른 답·자동 생각 등 재시작 후 유지할 설정.
- 마이크 녹음은 저장하는 개체가 없다(대화용 녹음은 메모리로만, 회의 녹음은 Meeting의 원음 파일).
- 보류: CompatibilityEvidence(토스 프론트).

## Success Criteria *(mandatory)*

### Measurable Outcomes

- SC-001: 미승인·거절·내용 변경 후·중복(동시 10회 포함) 실행 검사에서 잘못된 실행 0건.
- SC-002: 취소 뒤 이전 답변 재표시·재생 없음. (1단계는 모의 공급자 취소 후 추가 조각 0개)
- SC-003: 기억 저장·재조회·수정·삭제·재시작 후 검사 100% 통과, 삭제 기억 재노출 0건.
- SC-004: 네 공급자별 실제 API와 모의 검사 결과를 구분 보고.
- SC-005: Mac(M1 Max)과 Windows PC 각각에서 음성 지연·끼어들기 지연·CPU·메모리 실측. 수치 목표는 원본과 두 기기 초기 실측 후 확정.
- SC-006: 한국어 실제 청취와 기기 증거 없이 전체 QA 완료 선언 금지.
- SC-007: 재시작 후 대기·승인 미션 복원 100%, 완료 미션 재실행 0건.

## Assumptions

- 1단계 사용자는 한 명(로컬 단일 사용자)이며 로그인 기능은 없다.
- 1단계 미션 실행기는 실제 외부 작업을 하지 않는 모의·로컬 실행기다.
- 비밀 판별은 흔한 키 형태(예: `sk-`로 시작하는 긴 문자열) 기반 휴리스틱이며 완전하지 않다.
- 원본 확보 후 요구·우선순위가 바뀔 수 있다.
